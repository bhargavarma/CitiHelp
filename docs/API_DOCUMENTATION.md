# API DOCUMENTATION — Public Grievance AI Assistant

> **Project ID:** HACK-P438
> **Base URL (local):** `http://localhost:8000/api/v1`
> **Interactive docs:** `http://localhost:8000/docs` (Swagger UI) · `http://localhost:8000/redoc`
> **Content types:** `application/json`; `multipart/form-data` for uploads
> **Auth:** `Authorization: Bearer <JWT>`
> **Last Updated:** 2026-10-31

This is the authoritative endpoint reference. It matches the routes registered
in `backend/app/api/` and the schemas in `backend/app/schemas/`.

---

## 1. Conventions

### 1.1 Authentication

- Obtain a token with `POST /auth/login`.
- Send it on every protected request:

  ```http
  Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
  ```

- Tokens are HS256 JWTs with `sub` (user id), `email`, `role` and `exp`.
- Default lifetime: 1440 minutes (`ACCESS_TOKEN_EXPIRE_MINUTES`).
- Missing, malformed or expired tokens → `401`.
- Authenticated but wrong role → `403`.

### 1.2 Roles

| Role | Capabilities |
|------|--------------|
| Anonymous | Service directory, service detail, categories, health |
| `citizen` | Own profile, own grievances, attachments, tracking, AI chat |
| `admin` | Dashboard stats, all grievances, detail, status updates, chat (as a user) |

Public registration always creates a `citizen`. There is no public admin
registration endpoint. Admins are created with the bootstrap CLI/env.

### 1.3 Pagination

List endpoints accept `page` (≥ 1, default 1) and `page_size` (1–50, default 10)
and return:

```json
{
  "items": [],
  "total": 0,
  "page": 1,
  "page_size": 10,
  "total_pages": 0
}
```

### 1.4 Error shape

Domain errors:

```json
{ "detail": "Invalid email or password" }
```

Pydantic validation errors (`422`):

```json
{
  "detail": [
    {
      "type": "string_too_short",
      "loc": ["body", "password"],
      "msg": "String should have at least 8 characters",
      "input": "short"
    }
  ]
}
```

| Status | Meaning |
|--------|---------|
| 200 | Success |
| 201 | Created |
| 400 | Invalid category, status, or attachment |
| 401 | Missing / invalid / expired token, bad login |
| 403 | Wrong role, non-owner access, deactivated account |
| 404 | Resource not found |
| 409 | Duplicate email |
| 413 | Attachment too large |
| 422 | Request validation failed |
| 500 | Unhandled server error |

## 3. Authentication

### 3.1 Register citizen

```http
POST /api/v1/auth/register
```

Auth: none. Creates a `citizen` account. Any `role` field in the body is
ignored; the server forces `citizen`.

Request:

```json
{
  "email": "citizen@example.com",
  "full_name": "Rajesh Kumar",
  "phone": "9876543210",
  "password": "StrongPass123"
}
```

Validation:

| Field | Rule |
|-------|------|
| `email` | Valid email; stored lower-case; unique |
| `full_name` | 2–255 characters (trimmed) |
| `phone` | Optional, 7–20 characters |
| `password` | 8–128 characters, at least one letter and one digit |

Response `201`:

```json
{
  "id": "6f1c2a3e-7d4b-4c1a-9f2e-1a2b3c4d5e6f",
  "email": "citizen@example.com",
  "full_name": "Rajesh Kumar",
  "phone": "9876543210",
  "role": "citizen",
  "is_active": true,
  "created_at": "2026-10-31T10:15:00Z",
  "updated_at": "2026-10-31T10:15:00Z"
}
```

Errors: `409` duplicate email (case-insensitive), `422` validation failure.

### 3.2 Login

```http
POST /api/v1/auth/login
```

Auth: none.

Request:

```json
{ "email": "citizen@example.com", "password": "StrongPass123" }
```

Response `200`:

## 5. Grievances (Citizen)

All routes in this section require a valid token. Submission, attachments and
summary are **citizen-only**; listing/detail/history/tracking are available to
the owning citizen (admins may also read grievance detail and history).

### 5.1 List my grievances

```http
GET /api/v1/grievances?page=1&page_size=10&status=Submitted&search=water
```

Auth: any authenticated user; results are scoped to the caller's `user_id`.

| Query | Type | Notes |
|-------|------|-------|
| `page` | int ≥ 1 | Default 1 |
| `page_size` | int 1–50 | Default 10 |
| `status` | string | Case-insensitive status filter |
| `search` | string | Matches reference number, subject, category, location |

Response `200`: paginated `GrievanceResponse` items.

```json
{
  "items": [
    {
      "id": "8c2d1e4f-...",
      "reference_number": "GRV-20261031-A1B2",

      "attachment_path": "/uploads/5f0c...png",
      "current_status": "Submitted",
      "created_at": "2026-10-31T10:20:00Z",
      "updated_at": "2026-10-31T10:20:00Z",
      "citizen_name": "Rajesh Kumar",
      "citizen_email": "citizen@example.com"
    }
  ],
  "total": 1,
  "page": 1,
  "page_size": 10,
  "total_pages": 1
}
```

### 5.2 Submit a grievance

```http
POST /api/v1/grievances
```

Auth: **citizen only** (admins receive `403`).

Request:

```json
{
  "subject": "Broken drainage cover near primary school",
  "description": "The drainage cover has been missing for four days, creating a safety hazard.",
  "category": "Water Supply & Sanitation",
  "location": "Ward 7, Near Primary School",
  "attachment_path": "/uploads/5f0c1d2e3f4a5b6c7d8e9f0a1b2c3d4e.png"
}
```

| Field | Rule |
|-------|------|
| `subject` | 5–255 characters |
| `description` | 15–5000 characters |
| `category` | Must match one of the 11 allowed categories (case-insensitive) |
| `location` | 3–255 characters |
| `attachment_path` | Optional; must match `^/uploads/[A-Za-z0-9_.-]+$` |

Response `201`: `GrievanceResponse` with `current_status = "Submitted"` and a
generated `reference_number` (`GRV-YYYYMMDD-XXXX`). An initial
`grievance_history` row is written in the same transaction.

Errors: `400` invalid category, `403` admin/non-citizen, `422` validation.

### 5.5 Upload an attachment

```http
POST /api/v1/grievances/attachments
Content-Type: multipart/form-data
```

Auth: **citizen only**. Form field: `file`.

Allowed: JPEG, PNG, PDF; max `MAX_UPLOAD_SIZE_MB` (default 5 MB); non-empty.

Response `201`:

```json
{
  "path": "/uploads/5f0c1d2e3f4a5b6c7d8e9f0a1b2c3d4e.png",

```

Errors: `400` unsupported extension/MIME or empty file, `413` too large,
`403` non-citizen.

Typical flow: upload first, then pass the returned `path` as
`attachment_path` in `POST /grievances`.

## 6. AI Assistant

All chat routes require a valid token. Sessions and messages are private to the
owner; another user receives `403`. Admins do not get cross-user chat access.

### 6.1 Create a chat session

```http
POST /api/v1/chat/sessions
```

Request (body optional):

```json
{ "title": "Birth certificate inquiry" }
```

Response `201`:

```json
{
  "id": "3d4e5f6a-...",
  "title": "Birth certificate inquiry",
  "created_at": "2026-10-31T13:00:00Z",
  "updated_at": "2026-10-31T13:00:00Z"
}
```

### 6.2 List my chat sessions

```http
GET /api/v1/chat/sessions
```

Response `200`: array of `ChatSessionResponse`, newest first.

### 6.3 Read session messages

```http
GET /api/v1/chat/sessions/{session_id}/messages
```

Response `200`: array of `ChatMessageResponse` in chronological order.

```json
[
  {
    "id": "9a8b7c6d-...",
    "role": "user",
    "content": "What documents are needed for a Birth Certificate?",
    "sources": [],
    "created_at": "2026-10-31T13:01:00Z"
  },
  {
    "id": "1f2e3d4c-...",
    "role": "assistant",
    "content": "**Information Retrieved from Public Service Knowledge Base:** ...",
    "sources": [
      {
        "title": "Issuance of Birth Certificate",
        "source_url": "https://crsorgi.gov.in",
        "last_reviewed": "2026-08-15",
        "relevance_type": "Public Service Directory"
      }
    ],
    "created_at": "2026-10-31T13:01:01Z"
  }
]
```

Errors: `404` unknown session, `403` another user's session.

### 6.4 Send a message

```http
POST /api/v1/chat/sessions/{session_id}/messages
```

Request:

```json
{ "message": "What documents are needed for a Birth Certificate?" }
```

`message` is 1–2000 characters. The user message and the assistant reply are
persisted, and the response is the **assistant** message:

```json
{
  "id": "1f2e3d4c-...",
  "role": "assistant",
  "content": "The following documents are required: ...",
  "sources": [
    {
      "title": "Issuance of Birth Certificate",
      "source_url": "https://crsorgi.gov.in",
      "last_reviewed": "2026-08-15",
      "relevance_type": "Public Service Directory"
    }
  ],
  "created_at": "2026-10-31T13:01:01Z"
}
```

When no curated record matches, the reply states that no verified information is
available and `sources` is `[]`.

Errors: `404`, `403`, `422`.

### 6.5 Direct chat

```http
POST /api/v1/chat
```

Convenience endpoint: reuses the caller's most recent session, creating one if
none exists, then behaves like 6.4.

```json
{ "message": "How do I track my grievance?" }
```

Response `200`: assistant `ChatMessageResponse`.

### 6.6 General chat history

```http
GET /api/v1/chat/history
```

Returns the caller's most recent 30 messages across all sessions, ordered
chronologically.

## 7. Administration

Every route in this section requires `role == "admin"` (`403` otherwise).

### 7.1 Dashboard statistics / analytics

```http
GET /api/v1/admin/stats
GET /api/v1/admin/analytics
```

Both paths are aliases for the same real aggregate queries.

Response `200`:

```json
  "submitted": 10,
  "under_review": 8,
  "in_progress": 12,
  "resolved": 10,
  "rejected": 2,
  "pending": 30,
  "category_distribution": [
    { "category": "Water Supply & Sanitation", "count": 14 },
    { "category": "Roads & Infrastructure", "count": 9 }
  ],
  "recent_grievances": [
    {
      "id": "6e6649c5-...",
      "reference_number": "GRV-20261031-0042",
      "subject": "Broken drainage cover near primary school",
      "category": "Water Supply & Sanitation",
      "location": "Ward 7",
      "current_status": "Submitted",
      "created_at": "2026-10-31T09:12:00Z",
      "citizen_name": "Asha Rao",
      "citizen_email": "asha@example.com"
    }
  ],
  "recent_updates": [
    {
      "id": "a1b2c3d4-...",
      "grievance_id": "6e6649c5-...",
      "reference_number": "GRV-20261031-0042",
      "subject": "Broken drainage cover near primary school",
      "old_status": "Under Review",
      "new_status": "In Progress",
      "remarks": "Repair work started by the field team.",
      "changed_by_name": "Chief Grievance Officer",
      "created_at": "2026-10-31T12:05:00Z"
    }

```

- `pending` = submitted + under review + in progress.
- `recent_grievances` contains the five newest grievances.
- `recent_updates` contains the five newest history entries (audit feed).
- All values are computed with aggregate queries; an empty database returns
  zero counts and empty arrays.

### 7.2 List all grievances

```http
GET /api/v1/admin/grievances?page=1&page_size=10&status=Under%20Review&category=Water%20Supply%20%26%20Sanitation&search=ward&date_from=2026-01-01&date_to=2026-12-31&sort=newest
```

| Query | Type | Notes |
|-------|------|-------|
| `page` | int ≥ 1 | Default 1 |
| `page_size` | int 1–50 | Default 10 |
| `status` | string | Case-insensitive. A comma-separated group is accepted, e.g. `Submitted,Under Review,In Progress` |
| `category` | string | Case-insensitive |
| `search` | string | Reference number, subject, description, category, location, citizen name or citizen email |
| `date_from` | date (`YYYY-MM-DD`) | Inclusive lower bound on submission date |
| `date_to` | date (`YYYY-MM-DD`) | Inclusive upper bound on submission date |
| `sort` | `newest` \| `oldest` \| `status` | Default `newest`; `status` orders submitted → under review → in progress → resolved → rejected |

Response `200`: paginated `GrievanceResponse` items including `citizen_name`
and `citizen_email`. `total_pages` is `0` when no records match.

Errors: `400` for an invalid status value or when `date_from > date_to`,
`422` for an invalid `sort` or pagination value.

Pending queue example:

```http
GET /api/v1/admin/grievances?status=Submitted,Under%20Review,In%20Progress
```

### 7.3 Grievance detail (admin)

```http
GET /api/v1/admin/grievances/{grievance_id}
```

Response `200`: `GrievanceDetailResponse` with full complaint data, citizen name
and email, attachment path and history ordered **chronologically** (oldest
first). Errors: `404`.

### 7.4 Grievance history (admin)

```http
GET /api/v1/admin/grievances/{grievance_id}/history
```

Response `200`: array of `GrievanceHistoryResponse` records ordered
**chronologically** (oldest first). Each record contains `old_status`,
`new_status`, `remarks`, `changed_by_name` and `created_at`. Errors: `404`.

> The citizen endpoint `GET /grievances/{id}/history` remains newest-first for
> backward compatibility; the citizen detail page sorts it chronologically for
> display.

### 7.5 Update status

```http
PATCH /api/v1/admin/grievances/{grievance_id}/status
```

Request:

```json
{
  "status": "In Progress",
  "remarks": "Repair work started by the field team."
}
```

| Field | Rule |
|-------|------|
| `status` | One of `Submitted`, `Under Review`, `In Progress`, `Resolved`, `Rejected` (case-insensitive) |
| `remarks` | Optional, ≤ 2000 characters |

Response `200`: updated `GrievanceDetailResponse`.

Behaviour:

- The current status is updated **and** a `grievance_history` row is inserted
  with `old_status`, `new_status`, `changed_by`, remarks and timestamp.
- If `remarks` is omitted, a default administrative note is stored.
- History is append-only; previous transitions are never overwritten.

Errors: `400` invalid status, `404` unknown grievance, `403` non-admin.

## 9. Quick cURL Walkthrough

```bash
BASE=http://localhost:8000/api/v1

# Register and log in
curl -s -X POST $BASE/auth/register \
  -H "Content-Type: application/json" \
  -d '{"email":"citizen@example.com","full_name":"Rajesh Kumar","password":"StrongPass123"}'

TOKEN=$(curl -s -X POST $BASE/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"citizen@example.com","password":"StrongPass123"}' | jq -r .access_token)

# Browse services
curl -s "$BASE/services?search=birth"

# Submit a grievance
curl -s -X POST $BASE/grievances \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
```
